# 轻析 LiteOps

> 轻量化数据运营提效工作台——**不做看板，做 BI 之外的事**：临时取数、数据清洗、报告产出与知识沉淀，AI 辅助"需求进、报告出"。

## 这是什么

数据运营/商业分析岗位的日常里，看板和 BI 平台只覆盖了"固化指标"，而真正消耗时间的是大量**长尾、临时、一次性**的数据需求：

- 业务群里甩来一个 Excel："帮我把这 5 万行订单洗一下，下午要"
- 重复取数的 SQL 散落在各人的聊天记录和收藏夹里
- 报告里的数字靠人肉复制，出错无法溯源
- 需求靠口头/群聊流转，优先级全靠催，返工次数没人知道

**轻析把这些长尾工作收进一个本地工作台**：文件导入 → 自动体检 → 套用预设清洗 → 需求单管理 → AI 辅助构架报告 → 引用数据卡片 → 一键导出 Word/PDF，全流程数据可溯源。

## 五大模块

| 模块 | 能力 |
|---|---|
| **F1 数据存储** | Excel/CSV 导入（自动识别编码、字段类型推断、千分位/混合类型标记）；支持直连 MySQL/PostgreSQL 只读取数；文件分类、标签、口径备注 |
| **F2 数据清洗** | 去重、类型转换、日期标准化、缺失值处理、异常值过滤、字符串修剪等原子动作；内置场景化清洗预设；**五道安全闸**（体检先行/动作先预览/破坏性操作二次确认/原始文件只读/变更账本可回滚） |
| **F3 报告闭环** | 需求清单（紧急度×截止迫近度×业务方加权排序）→ 框架确认页 → 报告编辑器 → **引用数据卡片**（数字带来源，点击溯源）→ Word/PDF 导出 |
| **F4 SQL 片段库** | 常用 SQL 沉淀、分类检索、一键复制、使用计数；内置常用片段，支持团队共享 |
| **F5 文档库** | 业务文档/口径文件上传检索，需求分析时可引用 |

## 设计亮点

**1. AI 防幻觉硬约束（不是"提示词防一下"，是产品级拦截）**
- AI 仅用于报告"构架"（生成章节框架）与"精炼"（优化语言），**绝不接触原始数据行**
- AI 返回文本中的每个数字都过白名单校验：只允许出现"已引用的数据卡片数值"与"报告原文已有数字"
- 无来源数字自动红色高亮，悬停提示"无数据来源，请核对或删除"
- **存在无来源数字时禁止导出** Word/PDF——从流程上堵死"AI 编数字进报告"

**2. 清洗五道闸**
体检先行 → 每个动作先预览影响行数 → 删行删列二次确认 → 原始文件只读（清洗永远产出新文件）→ 变更账本记录每一步、可回滚。

**3. 本地优先，数据不出本机**
单机应用，SQLite 存储，双击启动、离线可用；AI Key 仅存本地数据库、可开离线模式完全关闭 AI；公网 Demo 仅为演示用途。

**4. 100 万行实测**
全链路分块读取（chunksize=5 万）+ pandas 向量化，100 万行 CSV 导入/体检/清洗不内存溢出。

## 技术架构

- **后端**：Python 3.11 + FastAPI + uvicorn，单端口 8000
- **存储**：SQLite（13 张表，零外部依赖）
- **前端**：Vue 3 全局构建版本 + 原生 CSS，**无 npm、无构建步骤、无前端路由**
- **数据处理**：pandas / openpyxl / chardet
- **导出**：python-docx（Word）、浏览器打印（PDF）
- **AI**：OpenAI 兼容协议（推荐 DeepSeek，自带 Key）
- **部署**：本地双击 `run.bat` 启动；同一套代码支持内网共享部署（Nginx + systemd）与公网 Demo（HTTP BasicAuth + 每日重置）
